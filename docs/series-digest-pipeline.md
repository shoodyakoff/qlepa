# Series Digest Pipeline

Новый пайплайн для каруселей-дайджестов в стиле «что нового» (референс — janeodud / odud.pro). Один пост = подборка апдейтов в едином визуальном языке: сквозной маскот, тёмно-синий заголовок с одним оранжевым словом, описательный интро-абзац, ряды иконок-выгод, спич-баблы, флоу «как это работает», сравнение старое→новое и финальный CTA.

Это **отдельный** жанр от editorial/artifact-rich (см. [`docs/pipelines.md`](pipelines.md)). Не смешивай `digest-*` и `slide-editorial` в одном посте.

## Когда использовать

- Подборка обновлений продукта/инструмента («что нового у X»).
- Дайджест-серия, где важна узнаваемость: один маскот, один ритм, один стиль слайдов.
- Пост, который хочется листать как новостную ленту: один апдейт = один слайд.

Если пост — это разбор одного процесса с пруф-объектами (файлы, карточки, системы), используй editorial/artifact-rich.

## Ритм серии (7 слайдов — как в референсе)

1. `digest-cover` — обложка-крючок: большой вопрос + подзаголовок + «Листай →», фото человек+маскот.
2.–6. `digest-update` — один апдейт на слайд. Заголовок + интро + список выгод, опционально маскот, спич-бабл, флоу, сравнение, чек-лист.
7. `digest-cta` — финал: заголовок + ряд иконок «что ты получаешь» + кнопка CTA + заметка.

## Типы слайдов и схема `post.md`

```md
## digest-cover
title: "Как я делаю 10 роликов за вечер"
subline: "Собрал всё, что реально работает"
scroll-cue: "Листай →"
image: "../../assets/generated/<hash>.png"   # фото: человек + маскот (текст добавляет рендерер)

## digest-update
badge: "СЦЕНАРИИ"                              # пилюля-кикер (опц.)
headline: |
  ПЕРЕД КАМЕРОЙ
  ЕСТЬ ДОКУМЕНТ                                 # 2 строки; строка 2 — оранжевый акцент
intro: "Описательный абзац на 2–3 предложения. Спокойный регистр, не телеграм."
accent-lines: "2"                              # какая строка заголовка оранжевая (по умолчанию 2)
image: "../../assets/generated/<hash>.png"     # сквозной маскот (опц.)
bubble: "Быстрее. Дешевле."                    # спич-бабл маскота (опц.)
features:                                       # иконка + выгода + пояснение
  - { icon: lightning, title: "Быстрее", desc: "меньше ручных переделок" }
  - { icon: target, title: "Точнее", desc: "каждый шаг задан заранее" }
checklist:                                       # «что это даёт» — строки с галочкой (опц.)
  - "Меньше переделок"
  - "Предсказуемый результат"
flow:                                            # «как это работает» — шаги слева направо (опц.)
  - { step: "Ввод", desc: "тема и цель" }
  - { step: "Сборка", desc: "по правилам" }
compare:                                         # старое→новое ✕/✓ (опц.)
  old-title: "Старая версия"
  old:
    - "Медленнее"
    - "Дороже"
  new-title: "Новая версия"
  new:
    - "Быстрее"
    - "Дешевле"

## digest-cta
headline: |
  10 РОЛИКОВ —
  10 МИНУТ
intro: "Процесс на 60% автоматический, остальное — пока руками."
image: "../../assets/generated/<hash>.png"
benefits:                                        # ряд иконок «что ты получаешь»
  - { icon: rocket, title: "Скорость", desc: "пачка за вечер" }
  - { icon: check, title: "Контроль", desc: "проверяю результат" }
cta:
  label: "→ как собрать такой же"
  url: "https://example.com"
note: "Больше разборов — в канале."
```

Все поля кроме `title` (cover) и `headline`+`intro` (update) опциональны — блок рендерится, только если поле есть. Пустой `image` деградирует в плейсхолдер, чтобы можно было проверить вёрстку до генерации арта.

### Иконки

`icon` берётся из набора имён (phosphor): `lightning`, `target`, `users`, `star`, `rocket`, `brain`, `robot`, `chart`, `search`, `check`, `pencil`, `shield`, `stack`, `film`, `mic`, `folder`, `sparkle` (+ синонимы вроде `speed`, `analytics`, `design`, `voice`). Неизвестное имя → `sparkle`.

## Дисциплина копии (тот же гейт, что у editorial)

Перед сборкой читать `brand/voice.md` и `brand/voice.local.md`. Для дайджеста — **описательный регистр**, как в референсе: 2–3 спокойных предложения в `intro`, без мата, без телеграм-маркеров, без рубленых однострочников.

Три слоя — три разных факта (это главная ошибка по памяти проекта):

- **headline** — заявление/поворот в 2 строки. Не объект-существительное, не пересказ интро.
- **intro** — что именно меняется и почему, описательно. Не пересказывает headline.
- **features / checklist / compare** — выгоды и конкретика, которых нет в headline и intro. `title` фичи — это **выгода**, а не голое название объекта.

Гейт `src/lib/carousel-quality.ts` (`validateDigestCopy`) валит сборку, если:
- headline и intro повторяют один факт;
- метка фичи повторяет headline или intro;
- любой слой содержит фразу из stop-list.

## Маскот: image-gen pass (Mode A)

Сквозной маскот нужен на обложке и апдейт-слайдах. Репозиторий сам картинки не генерит — агент готовит англоязычный промпт и путь кеша, человек сохраняет PNG.

1. Базовый промпт персонажа — `brand/prompts/series-mascot.md`.
2. Готовим промпты: обложка (человек + маскот) и сцены маскота для апдейтов.
3. `npm run carousel -- gen-photo series-mascot "<scene>" --no-wait` → копирует промпт и печатает путь `assets/generated/<hash>.png`.
4. Человек сохраняет PNG по этому пути, прописываем его в `image:` слайда.

До появления арта можно собрать первый проход с пустыми `image` (плейсхолдеры) — проверить вёрстку и копию. Финальный билд — после сохранения маскота. Не выдавать билд за финальный, пока значимые `image` пустые.

## Сборка

```bash
npm run carousel -- preview posts/starter-digest
npm run carousel -- build posts/starter-digest
```

PNG складываются в `posts/<slug>/out/` (`01-cover.png`, далее `NN-slide.png`).
