# Qlepa

Qlepa помогает собрать карусель для Instagram или Telegram из одного текстового файла. Вы пишете идею поста, добавляете референсы, смотрите превью и получаете готовые PNG-слайды в формате 4:5.

Проект работает локально на вашем компьютере. Личные фото, сгенерированные картинки и финальные PNG не попадают в git, а сам проект никуда их не загружает. Если вы работаете через Codex или Claude, фото попадут в чат только когда вы сами их туда отправите.

Если локальная папка у вас называется `images-codex`, это нормально. Переименовывать папку не нужно: публичное имя проекта теперь `Qlepa`.

## Что нужно от вас

Для первого запуска подготовьте:

- имя или название бренда;
- публичный ник, например `@your_handle`;
- ссылка на ТГ-канал или основной канал публикации;
- темы, про которые вы пишете;
- для кого вы пишете;
- тон текста: спокойно, дерзко, экспертно, разговорно и так далее;
- для фото-обложки: фото лица;
- для фото-обложки: фото в полный рост или по пояс;
- если не хотите обложку с собой: напишите `без моего фото`;
- опционально: картинку-референс композиции в том же outdoor-arrow стиле;
- идею первого поста или черновик текста.

Фото-обложка Qlepa не выбирается по настроению. В MVP есть один паттерн для обложки с человеком: `outdoor-editorial-arrow` — низкая камера, чистое синее небо, человек справа сверху, оранжевая стрелка/геометрия, крупный текст поверх. Цвета из других референсов можно использовать дальше в бренде, но не как альтернативные cover-настроения.

Фото лица и тела нужны только если нужна обложка с вами. Если пишете `без моего фото`, эти два файла можно не готовить.

Фото можно отправить прямо в чат Codex или Claude. Агент сам сохранит их в нужные папки. Если вы отправляете DNG, HEIC или другой raw-формат, агент должен сначала экспортировать/конвертировать их в JPG и сохранить как `assets/face-refs/face.jpg` и `assets/face-refs/body.jpg`.

## Первый запуск

Установите зависимости:

```bash
npm exec -- pnpm install
```

Проверьте проект и запустите онбординг:

```bash
npm run start
```

Если у вас установлен `pnpm`, можно так:

```bash
pnpm install
pnpm start
```

Команда `start` напечатает, что нужно прислать, проверит папки проекта и закончит статусом:

- `READY TO RUN` — технически репозиторий запускается, но это не значит, что Qlepa уже знает ваш бренд, tone of voice, ТГ-канал или фото;
- `NOT READY` — нужно исправить строки с `FAIL`;
- `WARN` по фото — нормально, если вы написали `без моего фото` или ещё не добавили референсы.

Если установка закончилась и вы хотите начать работу через Codex или Claude, напишите в чат: `старт`. Команды `/start`, `start`, `старт` должны запускать один сценарий Qlepa onboarding.

## Как работать через Codex или Claude

После установки откройте проект в Codex или Claude и вставьте:

```text
Прочитай README.md, docs/chat-onboarding.md, docs/agent-dialogue.md и AGENTS.md.
Онборди меня в Qlepa.
Спроси только то, чего не хватает для моего бренда и референсов.
Оставь стандартные локальные шрифты, если я сам не попрошу поменять типографику.
Когда npm run start покажет READY TO RUN, объясни, что это только техническая готовность репозитория. Спроси недостающие данные бренда, ТГ-канал, tone of voice и фото для единственной photo-cover схемы outdoor-editorial-arrow или явный ответ "без моего фото". Если бренд уже настроен, попроси идею поста или черновик.
```

Дальше отправьте ответы и изображения в чат. Агент:

1. зафиксирует ответ по фото-обложке: присланы фото или написано `без моего фото`;
2. сохранит фото в приватные папки, если нужна обложка с вами;
3. обновит брендовые настройки;
4. проверит проект;
5. попросит идею первого поста только после настройки бренда;
6. поможет собрать превью и финальные PNG.

Если вы просите агента только установить Qlepa, финальное сообщение после успешной установки должно быть простым: `Готово. Если хотите начать работу, напишите в чат: старт`.

Агент должен отвечать по-русски и не показывать служебные названия внутренних навыков, режимов, tool calls или workflow. Если его среда использует такие механики, они остаются внутри работы агента и не попадают в ответ пользователю.

## Фото-обложка

Обложка — это первый слайд поста, обычно `01-cover.png` в папке результата. Её не нужно отдельно хранить или вручную собирать заранее: Qlepa собирает обложку вместе со всеми слайдами поста.

В MVP нет выбора “настроения обложки” и нет кастомного cover brainstorm. Скрин с карточками настроений, редакторскими вариантами, ночной рефлексией или мягкими текстовыми подложками — неверный паттерн для фото-обложки Qlepa.

Единственный паттерн фото-обложки: `outdoor-editorial-arrow`. Это постер как на референсе: низкая камера, синее небо, человек в верхней правой части, много чистого места под типографику, оранжевая стрелка/геометрический объект снизу. Текст добавляет renderer Qlepa, поэтому generated image не должен содержать надписей.

Если человек пишет `без моего фото`, агент не делает photo-cover generation и не просит лицо/тело. Референс `style.jpg` опционален: он может уточнить композицию в том же outdoor-arrow стиле, но не вводит новый cover-режим.

## Куда складываются файлы

Приватные фото для фото-обложки с вами:

```text
assets/face-refs/face.jpg
assets/face-refs/body.jpg
assets/face-refs/style.jpg
```

`face.jpg` и `body.jpg` нужны только если хотите генерировать себя на обложке или слайдах. `style.jpg` можно не добавлять. Если исходники пришли как `.dng`, `.heic` или другой raw-формат, сохраните рабочие JPG-копии под этими именами.

Исходные сгенерированные картинки, которые могут использоваться внутри обложки или слайдов:

```text
assets/generated/
```

Готовые PNG после сборки:

```text
posts/<post-name>/out/
```

Например, финальная обложка будет лежать не в `assets/generated/`, а в папке поста как `posts/<post-name>/out/01-cover.png`.

Эти папки игнорируются git. Не кладите личные фото в другие места проекта.

Локальные рабочие посты вроде `posts/2026-05-25-mini-content-factory/` и их `out/` PNG — это авторская рабочая область. Они не становятся частью публичного репозитория и не превращаются в шаблоны автоматически. Шаблоны живут в `templates/`, а готовые PNG — это результат сборки конкретного `post.md`.

## Первый пост

Пример лежит здесь:

```text
posts/starter-post/post.md
```

Можно использовать его как подсказку по формату. Для нового поста лучше создать отдельную папку:

```text
posts/my-first-post/post.md
```

Если работаете через Codex или Claude, попросите агента создать папку и файл за вас.

## Почему появляется локальный сервер

`npm run start` не запускает dev-сервер. Это только онбординг и проверка готовности.

Сервер появляется в двух случаях:

- `npm run carousel -- preview <post-path>` запускает локальный Vite-сервер и держит его открытым, чтобы вы могли посмотреть реальные слайды поста в браузере.
- `npm run carousel -- build <post-path>` временно запускает тот же локальный рендерер, а Playwright открывает render routes и сохраняет скриншоты как PNG.

Страница `Template workbench`, которую можно увидеть на корне dev-сервера, — это технический список встроенных render routes: Cover, TextSlide, ListSlide, ImageSlide, QuoteSlide, EditorialSlide и FontSamplerSlide. Это не список всех пайплайнов и не готовый пост. Настоящий пост собирается из `posts/<post-name>/post.md`, а его визуальные формы выбираются полями слайда и React-шаблонами.

## Превью и экспорт

Посмотреть карусель в браузере:

```bash
npm run carousel -- preview posts/starter-post
```

Собрать PNG:

```bash
npm run carousel -- build posts/starter-post
```

Для своего поста замените `posts/starter-post` на путь к своей папке.

## Подготовка картинки для обложки или сцены

Проект пока не вызывает генерацию картинок сам. Если посту нужна картинка для обложки или внутреннего слайда, Qlepa готовит промпт, считает кеш и говорит, куда сохранить исходный PNG.

Для фото-обложки с человеком используйте только alias `cover`, он раскрывается в preset `outdoor-editorial-arrow`:

```bash
npm run carousel -- gen-photo cover "low-angle outdoor poster, clean blue sky, person in the upper-right, large matte orange arrow structure" --wardrobe "taupe overshirt, gray t-shirt, cap, dark glasses" --no-wait
```

Для внутренних сцен можно использовать другие presets вроде `generated-scene`, `character-scene`, `studio` или `lifestyle`, если это следует из slide brief.

Команда покажет английский промпт и путь вида:

```text
assets/generated/<hash>.png
```

Это не финальная обложка. Это исходная картинка, которую Qlepa потом вставит в первый слайд или другой слайд и соберёт финальные PNG в `posts/<post-name>/out/`.

Если нужна фото-обложка с вами, перед такой генерацией нужны `assets/face-refs/face.jpg` и `assets/face-refs/body.jpg`. Если написали `без моего фото`, эти файлы не нужны.

Объекты для картинки выбираются не случайно: сначала агент пишет смысл слайда (`reader-pain`, `mechanism`, `visual-route`, `visual-reason`), потом задаёт `visual.template`, `visual.primary`, при необходимости `visual.image`, и только после этого формулирует английский `scene` для `gen-photo`. Стиль берётся из `brand/prompts/<preset>.md`, необязательного `assets/face-refs/style.jpg`, wardrobe/style directives и конкретных слов в prompt.

Например, в локальной папке `posts/2026-05-25-mini-content-factory/` были слайды с generated scene и character/persona-вставками. Новый человек не получит эти локальные PNG из git, потому что `assets/generated/` и `posts/**/out/` игнорируются. Он получит тот же механизм: prompt preset, cache path, визуальные поля и render templates. Похожий результат можно собрать, если пройти тот же art-direction flow и сохранить свои generated PNG в `assets/generated/`, но идентичный робот не выбирается Qlepa автоматически и не восстановится из одного `post.md` без исходной картинки/промпта/референсов.

## Что можно не трогать

В первом запуске не нужно менять:

- `brand/fonts/` — локальные шрифты уже лежат в проекте;
- `brand/prompts/` — там базовые промпты для картинок;
- `templates/` — шаблоны слайдов;
- `src/` и `tests/` — код и проверки.

Обычно достаточно настроить:

- `brand/tokens.ts` — имя, ник, цвета, подписи;
- `brand/voice.md` или приватный `brand/voice.local.md` — голос автора;
- `assets/face-refs/` — ваши референсы, только если нужна фото-обложка с вами;
- `posts/<post-name>/post.md` — текст поста.

## Полезные команды

```bash
npm run start
npm run carousel -- preview posts/starter-post
npm run carousel -- build posts/starter-post
npm run carousel -- gen-photo cover "low-angle blue sky with orange arrow structure" --no-wait
npm run test
```

Если у вас установлен `pnpm`:

```bash
pnpm start
pnpm carousel preview posts/starter-post
pnpm carousel build posts/starter-post
pnpm test
```

## Что безопасно отправлять другому человеку

В репозитории можно хранить код, шаблоны, шрифты, промпты и пример `posts/starter-post/post.md`.

Не коммитьте:

- настоящие фото лица и тела;
- сгенерированные картинки из `assets/generated/`;
- финальные PNG из `posts/**/out/`;
- приватные посты;
- `.env`;
- `brand/voice.local.md`.
